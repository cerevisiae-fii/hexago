# HEXAGO AI 強化方針 — 「より強く・より軽量に」(v2.1.0)

作成: 2026-11-21 / 対象: `dev/ai-engine.js` ≡ `js/ai/engine.js` (MCTS v2.0.0 を土台に改良)
目的: 13路以上・3人以上が主戦場の現行AIの「守り偏重・死に石の攻め・無意味な着手で試合が長引く」を直し、
強さを保ちつつ計算量を大幅に削る。**強さの段階設定は持たない（最強1本）**。

---

## 1. まずルールの理解（このゲームの特殊性）

| ルール | 戦略的な帰結 |
|---|---|
| 六角盤（軸座標, 角3・辺4・中央6の呼吸点） | 角は最も早く2眼が作れる＝価値が高い。辺の一線は眼作りが容易だが発展がない |
| 得点 = **地 + 石**（面積得点/中国式） | 打った石そのものが1点。dameを取るのは純増(+1)。**自陣を埋めるのは±0（無意味）**。死に石は得点計算前に自動除去されるので、死ぬ侵入は純損ではないが±0（無意味） |
| コミなし・捕獲数は得点にならない | 石を生かすこと＝点数。殺し合いは「相手の石+地」の二重取り |
| 終局 = アクティブ全員の連続パス → `detectDeadStonesSmart` で死に石除去 → 採点 | **「どこに置いても点数が変わらない」状態で正解はパス**。着手を続けても面積得点では1点も動かない |
| 3〜6人対戦、投降は石を残したまま脱落 | 順位勝負。リーダーを攻める価値が上がる。他人同士の戦いは漁夫の利。無理な攻めは第3者に付け込まれる |
| 超劫判定は取った時だけ | 取り返しのコウは実質自由 |

**結論: 「囲碁はおける限り打つゲーム」ではなく「面積を最大化するゲーム」。自陣埋め・死に石・dame以外の埋め立てはすべて時間の無駄であり、正しい終盤は「利得>0の手だけを打ち、尽きたらパス」。**

## 2. 現行 v2.0.0 の病状（`dev/probe-behavior.js` で実証, 300ms/3000ms 両方で再現）

| プローブ | 状況 | v2.0.0 の着手 | 診断 |
|---|---|---|---|
| A | P1の確定した57点の自陣 + 広い中立地 | **(5,-1) 自陣の中を埋めた** | 自陣埋めが±0と評価できていない |
| C | 呼吸点2つの敵5子が無眼で放置され、殺し手が2箇所ある | **(0,-6) 遠くの隅の中立点 / (-5,0) 自陣埋め** | 攻撃（アタリ・締め）が探索候補・着手順から抜けている |
| D | 3人が壁で領地を確定（もう利得なし） | **P3の34点領地への自死侵入**、誰もパスしない | 死に石侵入が「有用」と判定される |
| E | 自陣26点 + 未取得のdameあり | **自陣を埋めた（dameを残した）** | TERR_SMALL(盤の12%)より大きい自陣は埋めてよい扱い |

根拠（コード）: `classifyRootMoves` の `useful` 判定が「領域が TERR_SMALL(=max(6, n*12%)) より大きければ useful」
→ 13路の15点超の自陣は全部「有用」になり埋められる。攻撃手は `patternScore` の切 (+72) しか優遇がなく、
呼吸点2〜3の敵連を締める手は root/tree/playout のどこでも候補化されない。

## 3. 方針 — 5本柱

### 柱1: 静的利得（static gain）で「意味のある手」だけを扱う
- ベースライン S0 = 「全員が今パスした場合の得点」（`removeDeadStones` → 地+石）。
- 各合法手 m の利得 `gain[m] = S(m)[自分] − S0[自分]`（着手→死に石除去→採点、の差分）。
  - dame = +1、敵の死に石の捕獲 = +石数+地、自陣埋め = ±0、眼埋め = ±0、死ぬ侵入 = 0。
- `useful` の定義を gain>0（＋アタリ回避の救済手）に置き換え、root 候補を useful に絞る。
  自陣埋め・眼埋め・死に侵入は探索候補から消える。

### 柱2: 侵入の生存可能性（viability）フィルタ — 「100%死に石」を打たない
- 敵色（自分を含まない色）だけで囲まれた領域への侵入は、
  `領域 ≥ V_MIN(盤寸法比例)` かつ `着手後の呼吸点 ≥ 3`（または捕獲を伴う／自石が距離2以内にいる）
  のときのみ「生きられる可能性がある」とみなす。それ以外は gain=0（死に石）として除外。
- 3路盤の小さい領地への浅い侵入・全滅確定の打入ちを機械的に禁止する。V_MIN 以上の大領地は
  MCTS が従来どおり判断する（守り薄なら侵入が成功するのは正しい）。

### 柱3: パス判定 — 「誰も得点を動かせない」を正確に検出
- 自分の最大利得 ≤ 0 かつ **他のアクティブプレイヤーにも利得>0の手が残っていない**
  （dame が残っていない・自分の領地に生存可能な侵入点がない・自分に取られかけの石がない）
  ⇒ 即パス（探索ゼロ・即応答）。
- 相手に利得が残るうちはパスしない（dame を取り合い、生存可能な侵入には先手で守る）。
  v2.0.0 が「相手パス後も自分の利得を無視してパスしていた」欠陥も同時に修正。
- 終盤のほとんどの手がこの判定で即決する＝**思考時間の大半を削減できる**（柱5）。

### 柱4: 攻めの制度化 — アタリ・呼吸点圧迫・リーダー攻撃（人数/盤面適応）
- root/tree 候補の順序に「敵連の呼吸点を減らす手」ボーナスを追加（対象: 呼吸点≤3・眼なしの
  敵連、ボーナスは連の大きさに比例）。playout も低優先度で呼吸点2の敵連を締める確率を追加。
- **3人以上**: 現在の面積上位者（リーダー）の石を攻めるボーナス ×1.25、最下位 ×0.7
  （順位最大化）。4人以上は安全係数を上げる（自ダメ手の拒否率↑、生きる最低呼吸点 2→3）。
- **盤サイズ**: 布石アンカーを半径比例にスケール（19/25路では3線→4〜5線相当）。
  序盤の重みは人数で調整（人数が多いほど中央の価値を下げ、角・辺の先占を重視）。

### 柱5: 軽量化 — 予算・並列・即断
- ページ側予算: 12s/15s(×最大8worker=1手最悪96コア秒) → **9路2.5s / 13路3s / 19路4s / 25路6s、
  worker は 4 上限**（root並列マージは維持）。
- 終盤の即断（柱3）と候補絞り込み（柱1）で実際の平均思考時間はさらに下がる。
- playout 速度は柱4の追加を除いて現状維持（過去実験で playout の質が強さに直結するため、
  削る方向のいじり方はしない）。

## 4. 検証基準（ベンチで数値化してから採用）

1. **強さ劣化なし**: 凍結 v2.0.0 (`bench/test/engines/hexago-mcts-2.0.0.js`) との A/B。
   - 2P9路 150ms/move ≥ 50%（64ゲーム以上）, 800ms スポット ≥ 45%
   - 3P13路 400ms/move ≥ 50%（本番条件に近い）
2. **行動指標**（`bench --style` 拡張メトリクス + probe）:
   - 自陣埋め（任意サイズの領域）: ≈0%（v2.0.0: probe A/E で自陣を埋めた）
   - 死に石侵入（小領域・呼吸点<3）: 0件
   - probe C: 呼吸点2の敵連を「アタリ手」で攻める
   - 完全確定局面でのパス: probe D で即パス
   - 平均着手数（13路3人）: v2.0.0 比で有意に減少
3. **正当性**: `dev/engine-selftest.js` 既存67項目 + 新規チェック（利得整合・パス条件・
   viability・probeアサーション）全合格。illegal/crash 0。
4. **軽量化**: 終盤 think() の playouts が 0（即断）になること、平均 ms/move の実測比較。

失敗時はオプション (`gainPolicy:false` 等) で段階的に戻せる設計にし、A/B で柱ごとに効きを測る。

### 測定で学んだこと（方針へのフィードバック）

- **playoutに「2呼吸点の敵を締める」確率を入れると弱くなる**（初期デフォルトで18.8% ← 全柱の残りより影響大）。
  強さの主因はplayoutの質という過去実験（notes §10）の再確認。攻めはroot順序＋確殺バイアスで担保する。
- **木展開への攻撃候補追加も弱くなる**（25%）。同上の理由でデフォルトOFF（オプション `treeAtk`）。
- **root候補の絞り込み（利得>0のみ）は、低予算では無害（150ms: ON/OFF同50%）だが
  高予算では明確に弱くなる**（800ms: 絞り込みON 25-37.5% vs OFF 62.5%）。
  探索の自由（深い侵入を証明する余白）を奪うと、読み深い regimes で損をする。
  → 最終設計: 絞り込みはオプション（`restrictCand`）とし、行動保証は
  「最終選択ガード（自陣埋め・死に侵入の差し替え）＋利得パスゲート」で担保する。
- 小盤面では V_DEEP=30（絶対下限）が61点盤を壊していた → 盤サイズで2段階（≤80点は n×0.15、
  それ以上は n×0.30）に修正。9路は壁が短く薄いので、ほぼ全領地が打入ち可能というのが実測。
- 敵石が盤上に1つもない場合、自グループの呼吸点≤2は「脅威」と数えない（当然だが初実装は漏れていた）。
- 9路2人150msでは互角、13路3人以上（主戦場）でも互角、800msレジームは最終設計で最終検証。
  ページ側の実効計算量は予算1/4・worker1/2・終盤即断で大幅に軽い。
